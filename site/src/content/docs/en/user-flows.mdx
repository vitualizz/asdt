# User Flows

## Getting a pipeline suggestion

Use `/asdt` when you're not sure which specialists a feature needs:

```
/asdt Add passwordless login with magic links
```

ASDT analyzes the request, assesses complexity and risk surface, and presents a routing plan — for example:

```
Recommended specialists:
  PM — define scope and acceptance criteria
  Architect — design token flow and API contracts
  Developer — implement the magic link handler
  Security — review the auth mechanism

Suggested order:
  /asdt-pm → /asdt-architect → /asdt-developer → /asdt-security

Proceed with this plan? (yes / modify / no)
```

Confirm the plan. ASDT then gives you the exact commands to run, in order, each carrying the same sharpened version of your request. **You run them — ASDT does not execute specialists automatically.**

## Running specialists directly

When you already know what you need, skip `/asdt` and invoke the specialist directly:

```
/asdt-architect Design the rate-limiting strategy for the API
/asdt-qa Review the checkout flow for edge cases
/asdt-security Audit the OAuth integration
```

Each specialist judges which of its own steps the request needs — the Developer, for example, stops at `explore` for a question, at `spec` for a plan, and only goes on to `approve → implement → verify` when you ask it to build — and saves its one hand-off to the knowledge base. Its report opens with what it built on and closes proposing the next specialist.

## Picking up mid-pipeline

If you ran some specialists and want to continue later, just invoke the next one. It reads prior artifacts from the knowledge base automatically — even from a previous session:

```
/asdt-developer Implement based on the Architect's ADR
```

The Developer reads the Architect's hand-off from the knowledge base. You don't pass context manually.

The same goes for a Developer plan. Ask for a plan and it is saved; come back later with `/asdt-developer "implement the plan we approved"` and it resumes at the approval gate instead of starting over.

## Memory and continuity

ASDT uses a memory provider to persist artifacts between specialists and across sessions. A memory provider is **required** for the pipeline to function. The default implementation is [Engram](https://github.com/Gentleman-Programming/engram). More providers are planned.

## Supported AI assistants

All slash commands work in both **Claude Code** and **OpenCode**. The syntax is identical in both tools.
