# User Flows

## Getting a pipeline suggestion

Use `/asdt` when you're not sure which specialists a feature needs:

```
/asdt Add passwordless login with magic links
```

ASDT analyzes the request, assesses complexity and risk surface, and presents a routing plan — for example:

```
Recommended specialists:
  PM — define scope and acceptance criteria
  Architect — design token flow and API contracts
  Developer — implement the magic link handler
  Security — review the auth mechanism

Suggested order:
  /asdt-pm → /asdt-architect → /asdt-developer → /asdt-security

Run this chain? I'll pause after each specialist.
```

Each command carries the same sharpened version of your request. Say yes and `/asdt` runs the chain one specialist at a time, **pausing after each one**: you can debate the result, and it moves on only on your go (or to whichever specialist the debate made more urgent). Or run the commands yourself, in order. **Nothing runs without your yes.**

## Running specialists directly

When you already know what you need, skip `/asdt` and invoke the specialist directly:

```
/asdt-architect Design the rate-limiting strategy for the API
/asdt-qa Review the checkout flow for edge cases
/asdt-security Audit the OAuth integration
```

Each specialist judges which of its own steps the request needs — the Developer, for example, runs no step for a question, stops at `spec` for a plan, and only goes on to `approve → implement → verify` when you ask it to build, skipping `explore` and `spec` when a quick read of the code shows the change is small — and returns its one summary, which the orchestrator writes to the session scratchpad for the next specialist. Its report opens with what it built on and closes proposing the next specialist.

## Picking up mid-pipeline

If you ran some specialists and want to continue, just invoke the next one. In the same session, it reads the earlier summaries from the scratchpad:

```
/asdt-developer Implement based on the Architect's design
```

The Developer gets the Architect's summary as an input. You don't pass context manually. In a later session the scratchpad may be gone, which is normal: the Developer works from the code, git, and the key decisions memory recalls, and asks you for anything else it needs.

The same goes for a Developer plan. Ask for a plan and the run stops there; come back later with `/asdt-developer "implement the plan we approved"` and it resumes at the approval gate instead of starting over. If the session ended in between, it rebuilds the plan from git, memory, and your words, and you approve the rebuilt plan.

## Memory and continuity

Within a session, specialists hand work to each other through summaries in the session scratchpad. Across sessions, a memory provider keeps only the key project knowledge: non-obvious decisions, debate conclusions, conventions, lessons, and audit findings. The current provider is [Engram](https://github.com/Gentleman-Programming/engram). Without a connected provider, ASDT still works within the session; nothing carries over. See [Scratchpad & Memory](/asdt/docs/memory-and-engram).

## Supported AI assistants

All slash commands work in both **Claude Code** and **OpenCode**. The syntax is identical in both tools.
