# Getting Started

## Requirements

Before using ASDT, you need:

- **Claude Code** or **OpenCode** — installed and authenticated (these are the only assistants ASDT targets today)
- **A memory provider** (optional, recommended) — carries key project knowledge (decisions, conventions, lessons) across sessions. The installer offers [Engram](https://github.com/Gentleman-Programming/engram). Without one, ASDT still works within each session
- **A code-intelligence provider** (optional) — an index of your code that answers symbol and structure questions in one call instead of grep-and-read loops. The installer offers [Codegraph](https://github.com/Gentleman-Programming/codegraph). Without one, specialists grep and read
- A terminal (bash or zsh)

> **Building from source?** Go 1.22+ is required. Running the one-line installer downloads a pre-built binary — no compiler needed.

## Installation

```bash
curl -fsSL https://raw.githubusercontent.com/vitualizz/asdt/main/install.sh | bash
```

Downloads the latest pre-built binary (`asdt-tui`) for your platform and installs it to `~/.local/bin/`. No Go or compiler needed.

> If `~/.local/bin` is not on your `PATH`, the installer prints the exact line to add to your shell profile.

## Run the installer

```bash
asdt-tui
```

`asdt-tui` is an interactive terminal UI. From the main menu, choose **Install / Update Skills** and it walks you through a short guided flow:

1. **Language** — pick the language ASDT speaks in: `en` (English), `es-419` (Latin American Spanish), or `es-ES` (peninsular Spanish). Your choice drives both the installer UI and the installed specialists.
2. **Environment check** — probes your OS, shell, every memory provider (Engram), and every code-intelligence provider (Codegraph). Nothing here blocks you: a missing provider is a warning with its install link.
3. **Assistants** — choose which to target: **Claude Code**, **OpenCode**, or both. Each shows a present/missing badge.
4. **Providers** — one screen, two choices. **Memory**: pick Engram or **No memory**. The default is Engram when it is on your `PATH`, otherwise No memory. You can pick Engram before installing it: the installer warns and shows the install link, and memory works once Engram is connected. A provider is recommended because it keeps key project knowledge between sessions. **Code intelligence**: pick Codegraph or **No code intelligence**, defaulting the same way. Specialists query the index only in a project it has indexed; everywhere else they grep and read.
5. **Model preset** — pick how much model horsepower each specialist step uses (see below).
6. **Persona** — optionally pick a persona for the installed assistants, and whether they should use emojis. It goes into your global `CLAUDE.md` / `AGENTS.md` as one marked block; the rest of the file is never touched. If the file already exists, you choose per assistant to update ASDT's block or skip it. You can skip this step entirely (see [The agent config](/asdt/docs/ai-assistants#the-agent-config-both)).
7. **Review → Install → Done** — confirm your selections, watch the install run, and you're set. The **Dashboard** on the main menu shows per-assistant status any time, and removes ASDT's agent config block (`r`) when you no longer want it.

> **Fewer approval prompts on Claude Code:** run it in **auto mode**, where a classifier lets routine actions through and blocks risky ones; ASDT's sub-agents inherit it. ASDT's own gates (approving the Developer's plan, approving verification commands) stay in every mode. Never use `bypassPermissions` on your host. See [Permission prompts](/asdt/docs/ai-assistants#permission-prompts-claude-code).

## Initialize your project

Open your AI assistant in your project folder and run:

```
/asdt-init
```

It detects your stack, asks a couple of questions, and writes `.asdt/config.yaml` with sensible defaults.

## Your first pipeline

```
/asdt Add user authentication with email and password
```

ASDT analyzes the request and recommends a specialist sequence — for example: `/asdt-pm` → `/asdt-architect` → `/asdt-developer`. Say yes and it runs that chain one specialist at a time, pausing after each so you can push back; or run each command yourself. Each specialist's summary goes to the session scratchpad, so the next one picks up where the previous left off.

## Running individual specialists

```
/asdt-pm Add dark mode to the settings page
/asdt-architect Design the caching strategy
/asdt-developer Implement the user profile component
```
